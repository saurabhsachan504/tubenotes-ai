Pick your "Quick Summary" transformation here. This skips the chat/retrieval step entirely and generates the on-the-spot summary directly from the transcript with a fast model — much quicker.
Pick a smaller/faster model here (e.g. a 7B model) so answers come back quickly. Leave as System default if unsure. Tip: if you add a hosted fast model (Gemini Flash, Claude Haiku, etc.) to Open Notebook, it will show up here and you can select it for more consistent low latency.
Skips the embedding step and polls aggressively so the on-the-spot summary comes back much faster. Summaries don't need embeddings, so this is safe. Turn it OFF only if you rely heavily on RAG-based chat follow-up questions, which work better with embeddings.
Shows the summary token-by-token as it's generated (first text in ~2-3s) instead of waiting for the whole thing. Total time is the same, but it feels much faster. If OFF, the summary arrives all at once via the quick-summary transformation.
Shows a short summary in a few seconds so you can start reading, then quietly generates the full detailed summary and swaps it in when ready. If OFF, only the single "detailed" summary below is generated.
Drives the fast first-pass summary. Keep it small (few short bullets) so it returns in a few seconds. Leave blank for the built-in default.
Drives the full detailed summary. Put your longer, structured prompt here. Leave blank to reset to the built-in default.
How many parts of the transcript are written at the same time. This can't beat your server: Ollama runs OLLAMA_NUM_PARALLEL requests at once and queues the rest, so setting this higher than that number buys nothing. Default 4. While a PDF builds it uses these slots, so a chat message started at the same moment waits behind it — drop this to 3 to keep one slot free for chat.
