TubeNotes Chrome Extension v2.2.0 — vLLM migration

Active summary flow:
Chrome Extension -> https://tubenotes.trueworks.in/api/v1/summarize
-> TrialGuard backend -> VLLM_URL/chat/completions -> VLLM_MODEL

Active PDF/full-notes flow:
Chrome Extension -> https://tubenotes.trueworks.in/api/v1/notes
-> TrialGuard backend -> vLLM -> local Markdown download + browser print/PDF tab

Backend production values (keep these on the server, NOT in the extension):
VLLM_URL=http://gemma4:8000/v1
VLLM_MODEL=gemma4-summarizer

Changes in this build:
- Summary generation uses TrialGuard's authenticated vLLM-backed /summarize stream.
- Full PDF notes use TrialGuard's authenticated vLLM-backed /notes stream.
- Browser transcript is sent to the backend when available to skip server-side YouTube transcript fetching.
- Summary tokens render live from NDJSON streaming.
- PDF progress is updated from backend progress events and survives side-panel hiding via the service worker.
- Removed Ollama localhost/11434 host permissions.
- Model URL/model are no longer exposed or required by the active summary/PDF path in the extension.
- Existing account/trial/subscription flow remains shared with the web app.

Important:
The current TrialGuard backend must expose /api/v1/summarize and /api/v1/notes and be configured with the VLLM_URL/VLLM_MODEL values above.
